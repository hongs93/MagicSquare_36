## 1. 목적

FR-01~FR-05 전 범위에 대해 **Dual-Track RED** 테스트 설계를 고정한다.

| Track | 대상 | RED Test ID 접두 |
|-------|------|------------------|
| **A** | Boundary — 입력 검증(U-IN-*), 출력 계약(U-OUT-*), 흐름 격리(U-FLOW-*) | U-IN, U-OUT, U-FLOW |
| **B** | Entity/Control — 빈칸·누락·마방진 판정·2조합 솔버 | D-LOC, D-MIS, D-VAL, D-SOL |

핵심 원칙:

- Boundary invalid → **Failure envelope** (Python 예외 아님)
- invalid 입력 시 `SolvePartialMagicSquare.execute` **0회** (U-FLOW-02)
- Logic Track → **Domain Mock 금지**
- 검증 short-circuit: `null` → `size` → `empty count` → `value range` → `duplicate`

## 2. 프로젝트 계약 (워크숍 SSOT)

### 2.1 입·출력

| 항목 | 규칙 |
|------|------|
| 입력 | 4×4 `int[][]`, `0`=빈칸(정확히 2개), 값 `0` 또는 `1..16`, non-zero 중복 금지 |
| 출력 | `int[6]` = `[r1,c1,n1,r2,c2,n2]`, 좌표 **1-index** |
| 마방진 상수 | 4×4 → M=34 (`MagicConstant` SSOT) |

### 2.2 Boundary 오류 코드 (프로젝트 계약)

| 순서 | 조건 | Code | Message (exact) |
|------|------|------|-----------------|
| 1 | `matrix=null` | `E003_NULL_INPUT` | `Input matrix must not be null.` |
| 2 | size ≠ 4×4 | `E001_INVALID_SIZE` | `Input matrix must be 4x4.` |
| 3 | 빈칸(0) ≠ 2 | `E002_INVALID_BLANK_COUNT` | `Exactly two blanks (0) are required.` |
| 4 | 값 ∉ {0}∪{1..16} | `E004_INVALID_RANGE` | `Values must be 0 or 1..16.` |
| 5 | non-zero 중복 | `E005_DUPLICATE_NONZERO` | `Non-zero values must be unique.` |

> **주의:** PRD §13은 null을 `E001`에 매핑하지 않음. 본 설계는 **워크숍 계약(E003=null)** 을 따른다. 기존 AC-FR-01-01 RED(`INVALID_SIZE` for null)와 충돌 시 SSOT 정렬 필요.

### 2.3 Domain Logic 별칭 (구현명 미확정)

| 설계 별칭 | 책임 | Invariant |
|-----------|------|-----------|
| `find_blank_coords()` | EmptyCellLocator | I6 |
| `find_not_exist_nums()` | MissingNumberFinder | I7, I11 |
| `is_magic_square()` | MagicSquareValidator | I1~I5 |
| `solution()` | TwoCellSolver / Use Case | I8~I10 |

```text
[[ 1,15,14, 4],
 [ 8,10,11, 5],
 [12, 6, 7, 9],
 [13, 3, 2,16]]
```

### 3.2 G1

```text
[[ 1,15,14, 4],
 [ 8, 0,11, 5],
 [12, 6, 0, 9],
 [13, 3, 2,16]]
```

- 0-index blanks: `(1,1)`, `(2,2)` → 1-index `(2,2)`, `(3,3)`
- 누락: `{7, 10}` 오름차순
