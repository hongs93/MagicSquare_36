## 1. 목적

4x4 Magic Square TDD Practice를 단순 알고리즘 풀이가 아닌, 불변식 기반 설계 훈련 흐름으로 운영하기 위해 상위 요구 구조를 단계별로 정의한다.

핵심 목적:
- Epic -> User Journey -> User Story -> Scenario의 추적 가능한 계층 확립
- Boundary와 Domain 책임 분리 명확화
- 계약(입력/출력/오류)과 불변식 중심 검증 기준 정렬

---

## 2. 산출물 요약

### 2.1 Level 1: Epic
- Epic Title: 불변식 기반 사고 훈련 시스템 구축
- Business Goal: 설계/계약/검증 중심 개발 사고 체계화
- Learning Goal: Concept -> Invariant -> Contract -> Test 추적성 훈련
- Success Criteria:
  - Domain Logic 테스트 커버리지 95% 이상
  - Boundary 입력 검증 계약 테스트 100% 통과
  - 설명 없는 매직 넘버 금지, 명명된 상수 사용
  - 정답 하드코딩 금지
  - 리팩토링 후 외부 I/O 계약 불변

### 2.2 Level 2: User Journey
5단계 여정으로 정의:
1. Problem Recognition
2. Contract Definition
3. Domain Separation
4. Dual-Track TDD Progress
5. Regression Protection

각 단계는 Action/Thinking/Emotion/Pain Point/Opportunity 및 학습 성과를 포함해 작성했다.

### 2.3 Level 3: User Stories
총 5개 Story를 Boundary/Domain로 분리해 정의:
- Story 1 입력 검증 (Boundary)
- Story 2 빈칸 좌표 탐색 (Domain)
- Story 3 누락 숫자 탐색 (Domain)
- Story 4 마방진 검증 (Domain)
- Story 5 두 가지 조합 시도 (Domain + Boundary Output)

각 Story에 테스트 가능한 Acceptance Criteria와 보호 Contract/Invariant를 명시했다.

### 2.4 Level 4: Implementation Scenarios (Technical)
정의된 시나리오:
- SC-DOM-SOL-001: small-first 실패 후 reverse 조합 성공
- SC-BND-VAL-001: 빈칸 개수 오류
- SC-BND-VAL-002: 중복 숫자 오류
- SC-BND-VAL-003: 범위 위반 오류

각 시나리오는 Related Story, Layer, 보호 규칙, Future RED Test ID 후보, Future Task 후보를 포함한다.

---

## 3. 핵심 규칙 정렬

### 3.1 Domain Invariants
- 4x4 고정 격자
- 값 범위: 0 또는 1..16
- 0 제외 중복 금지
- 빈칸(0) 정확히 2개
- 마방진 합 상수 34
- small-first 실패 시 reverse 조합 재시도

### 3.2 Boundary Contracts
- 입력 계약 위반 시 검증 실패 처리
- 검증 실패 입력은 Domain Solver 미전달
- 출력 계약은 int[6], 1-index, [r1, c1, n1, r2, c2, n2] 고정

---

## 4. 추적성 구조

정의한 추적성 체계:
- Epic Goal -> Journey Stage -> User Story -> Acceptance Criteria -> Scenario -> Future RED Test

기대 효과:
- 요구사항 단위별 검증 가능성 확보
- 리팩토링 시 계약/불변식 회귀 감시 용이
- 학습자가 "정답 산출"보다 "규칙 보존" 중심으로 사고하도록 유도
