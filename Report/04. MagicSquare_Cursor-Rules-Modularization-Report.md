## 1. 목적

기존 단일 파일 규칙(`.cursorrules`) 중심 운영에서, 목적별 규칙 분리와 파일 맥락 기반 적용을 위해 Cursor Rules를 모듈형(`.cursor/rules/*.mdc`)으로 전환한다.

핵심 목표:
- 규칙 관심사 분리 (project/style/architecture/tdd/forbidden)
- 파일 패턴 기반 규칙 적용 (`globs`)
- alwaysApply 최소화로 규칙 충돌 및 과도한 컨텍스트 감소

## 3. 규칙 반영 요약

### 3.1 code_style
- Python 3.10+
- PEP8 엄격 준수
- 모든 함수 파라미터/반환값 type hints 필수
- public 메서드 Google 스타일 docstring
- max line length 88 (Black 기준)

### 3.2 architecture (ECB)
- boundary: 외부 입출력 (UI, API, CLI)
- control: 비즈니스 로직 오케스트레이션
- entity: 도메인 데이터/규칙
- 의존성 방향: `boundary -> control -> entity`
- 금지 방향: `entity -> control/boundary`, `control -> boundary`

### 3.3 tdd_rules
- phase_red: 실패 테스트 선행
- phase_green: 최소 구현으로 통과
- phase_refactor: 동작 보존 리팩터링
- 각 phase는 `description`, `rules`, `must_not` 하위 구조로 세분화

### 3.4 testing
- framework: pytest
- pattern: AAA
- coverage_minimum: 80%
- fixture_scope 규칙 포함
- naming_convention: `test_` 접두사 필수

### 3.5 forbidden
구조: `pattern`, `reason`, `alternative`
- `print()` 디버깅 금지
- 하드코딩 상수 직접 사용 금지
- `except:` 단독 사용 금지
- 테스트 약화 금지

### 3.6 file_structure / ai_behavior
- ECB 기준 트리 구조 주석 제공
- 코드 생성 전/중/후 AI 체크 규칙 정의
- TDD 위반 감지 시 경고 출력 규칙 포함
